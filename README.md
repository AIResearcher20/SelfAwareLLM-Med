# SelfAwareLLM-Med

Evaluating semantic self-consistency as a potential reliability signal for medical large language models.

This is a research prototype. It is not a validated clinical tool.

## Status

Results below were generated by this repository on 2026-10-15. They have not been independently reproduced.

## Question

Can semantic agreement among multiple responses generated by a medical QA model predict the quality of a separately generated answer?

Consistency is measured as the mean pairwise cosine similarity between embeddings of several responses to the same question. Quality is measured two ways: multiple-choice accuracy against the gold answer, and ROUGE-L against the reference answer text.

## Headline result

Across 250 USMLE-style questions with llama3.2:3b, consistency is positively correlated with multiple-choice accuracy and negatively correlated with ROUGE-L. Two surface-level and correctness-level metrics point in opposite directions.

| method   | n   | rho(accuracy) | p(accuracy) | rho(ROUGE-L) | p(ROUGE-L) | mean accuracy |
|----------|-----|---------------|-------------|--------------|------------|---------------|
| adaptive | 250 | 0.133         | 0.035       | -0.208       | 0.0009     | 0.508         |
| auas     | 250 | 0.293         | 2.5e-06     | -0.069       | 0.277      | 0.444         |
| fixed    | 250 | 0.228         | 0.00027     | -0.185       | 0.0033     | 0.512         |

auas is the only method whose correlation with accuracy is stable across sample sizes (rho=0.329 at n=50, rho=0.293 at n=250). adaptive dropped from rho=0.421 at n=50 to rho=0.133 at n=250, which shows that n=50 was not enough for this analysis.

## Second finding: early stopping predicts correctness

Within the adaptive methods, questions that reached the consistency threshold in 4 samples had much higher accuracy than questions that ran to the cap.

| method   | accuracy at n=4 samples | accuracy at n=5 samples |
|----------|-------------------------|-------------------------|
| adaptive | 0.708 (65 questions)    | 0.438 (185 questions)   |
| auas     | 0.759 (58 questions)    | 0.349 (192 questions)   |

The stopping mechanism itself carries information that the consistency score alone does not.

## Third finding: consistency groups separate

Each method's 250 questions were split at the median consistency into a low and a high group.

| method   | accuracy (low cons.) | accuracy (high cons.) | gap    |
|----------|----------------------|-----------------------|--------|
| adaptive | 0.464                | 0.552                 | +0.088 |
| auas     | 0.328                | 0.566                 | +0.238 |
| fixed    | 0.440                | 0.584                 | +0.144 |

## Methods

Three samplers are implemented:

- **fixed**: exactly N consistency samples, then one evaluation response.
- **adaptive**: draws consistency samples one at a time, stops when mean pairwise similarity reaches a threshold or a maximum is hit, then one evaluation response.
- **auas**: same stopping behavior expressed as an uncertainty threshold (1 - consistency). Included for comparison, not as a novel algorithm.

The evaluation response is an extra model call per question per method. It is not counted in the consistency sample count. Total call counts are recorded per row.

Config used for the reported run:

- consistency temperature: 1.0
- evaluation temperature: 0.7
- adaptive: threshold 0.85, min_samples 4, max_samples 5
- auas: uncertainty threshold 0.15, min_samples 4, max_samples 5
- fixed: 5 consistency samples
- seed: 13

## Models

- generation: llama3.2:3b via Ollama
- embeddings: nomic-embed-text via Ollama

Both run locally. No paid API is used anywhere in this repository.

## What is recorded per row

qid, method, consistency, rouge_l, accuracy, n_consistency_samples, stop_reason, valid_responses, failed_responses, generation_calls, embedding_calls, latency_s, error, evaluation_starts_with_letter.

Raw model responses are stored in `responses_{method}.csv`.

Errors are never converted into empty strings. A failed generation or embedding is counted and marked.

Total run: 250 questions x 3 methods = 750 runs, 4377 generation calls, 699 embedding calls, 0 errors, ~78 minutes wall clock on a free GitHub-hosted runner.

## Reproducing

Install:

    pip install -r requirements.txt
    pip install -e .

Build the sample dataset once (needs network and the datasets package):

    pip install datasets
    python scripts/build_sample.py

Start Ollama and pull the models:

    ollama pull llama3.2:3b
    ollama pull nomic-embed-text

Run:

    python -m selfaware_med.cli --config configs/experiment.yaml --out-dir results

## Running in CI

`.github/workflows/ci.yml` runs lint and unit tests on every push. It does not download models and does not need network beyond pip.

`.github/workflows/experiment.yml` is triggered manually from the Actions tab. It installs Ollama, caches the models, runs the experiment on a chosen number of questions, and uploads results as artifacts. Free GitHub-hosted runners are CPU-only and time-limited; start with a small number of questions.

## Limitations

- Consistency measures semantic resemblance, not truth.
- ROUGE-L measures surface overlap, not medical correctness.
- The evaluation target is the reference-based score of one independently generated answer, not the consistency sample set itself.
- consistency=1.0 does not guarantee a correct answer. Several questions had full agreement on the wrong choice.
- Reported correlations are weak. For auas at n=250, r-squared is roughly 0.09.
- Multiple comparisons were not corrected in the reported p-values. After Bonferroni correction (alpha=0.017 for three methods), only auas and fixed remain significant for accuracy.
- llama3.2:3b answers 44-51% of these questions correctly. ROUGE-L mean is 0.09-0.11.
- Ollama does not guarantee identical outputs across versions or hardware even with a fixed seed.
- The MedQA subset used here is English and multiple-choice. It is not a substitute for clinical evaluation.
